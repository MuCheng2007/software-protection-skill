# AI 逆向与虚拟化保护的审查

用于评估“防 REA / 防 AI”、组合混淆、VMProtect 等虚拟化方案。先按 F12 查最终产物，再用本页判断保护收益与验证可信度；不要求安装特定逆向工具。

## 区分攻击目标与分析路线

分别评价核心算法保密、授权执行、服务端资源访问。恢复一个函数，不等于恢复整个软件；绕过本地判断，也不等于取得服务端权限。

静态阅读失败后，分析者仍可能使用运行观察、模拟执行、数据流分析或局部重写。审查输入到真实业务输出的数据依赖，不只看反编译代码是否难读。将机器指令翻译成中间表示，再做常量传播、活跃分析和表达式化简，是可复用的语义恢复路线；具体虚拟指令解码、上下文映射、调用及入口出口仍可能需要版本适配。[Remill](https://github.com/lifting-bits/remill)、[MogVMP](https://github.com/eversinc33/MogVMP)

恢复模型须保留标志位、栈、重叠寄存器、内存别名、外部调用与可观察副作用。GEP 计算地址，不会自动恢复业务语义；随意把未知状态设为 undef，可能把有用行为一起优化掉。局部表达式的等价性不证明完整程序等价。[LLVM GEP](https://llvm.org/docs/GetElementPtr.html)、[LLVM 语言参考](https://llvm.org/docs/LangRef.html)

## 选择加固措施

1. 先移除客户端不应拥有的签发秘密，修复真正业务边界上的授权。可联网时评估把不可替代计算留在提供方控制的服务端；后端仍须鉴权、约束租户与配额、防重放。仅下发布尔值、可复用常数或密钥不能建立同等边界。
2. 对必须本地执行的高价值函数选择组合混淆、虚拟化及完整性措施；按攻击成本、运行耗时、体积、兼容性、误判与诊断成本选型。没有目标产物上的测量，不给出固定降本百分比、固定检测点数量或“某组合必定防住当前 AI”的结论。
3. 运行环境信号可能增加观察成本，但不是天然秘密或可信身份。普通本地地址、系统信息和检测结果可被观察、模拟或修改；检查地址随机化、重启、更新及合法设备差异，避免密钥派生不稳定。
4. 诱饵和误导至多是依赖分析者行为的成本措施，不代替授权。正式业务拒绝时应可诊断、可恢复，不静默生成错误的工程、财务、医疗或用户数据结果；不要用伪造成功损害正常用户。

## 从分析工作流反推暴露面

针对打包程序、解释器运行时或能调用调试工具的 Agent，建立“容器 → 加载器 → 语言运行时 → 业务逻辑 → 结果消费”的层次图。把实际执行进程、模块、函数/接口、可观察数据和授权执行方填入图中；没有项目证据的部分标为待验证。入口改名、假脚本或把逻辑搬到运行库，不能单独作为保密措施。

对核心能力建立暴露表：资产、首次出现位置、读取者、明文生命周期、是否可复用、最终消费点、控制方及验收方法。重点包括解释器帧/代码对象、原生调用边界、解密后缓冲、配置缓存和业务响应。减少不必要的完整秘密下发与保留；缩短明文寿命只能减少暴露窗口，不能保证无法被捕获。

| 观察面 | 防御决策 | 剩余限制 |
| --- | --- | --- |
| 归档、资源、运行库和调试材料 | 检查最终发布清单，排除私钥、管理凭据、测试答案及无须公开的符号资料；保留内部诊断副本 | 隐藏字符串和标识符不能阻止按实际行为定位 |
| 解释器帧、字节码、局部变量 | 检查核心逻辑是否全部处于可检查的运行时；必要时评估局部原生实现或提供方服务端计算 | 原生化降低高级语义直接暴露，不等于算法不可恢复 |
| 调用、解密与结果边界 | 追踪最终消费的数据与生产者，减少长期可复用的秘密材料 | 客户端必须使用的明文仍可能被观察；反调试/反插桩按成本措施评价 |
| 本地校验结果与真实付费操作 | 模拟本地结果被替换后，检查提供方后端是否仍独立授权新任务 | 不能保证修改后的界面不开启；目标是拒绝未授权能力 |
| 合法响应和历史缓存 | 评估保存一次合法运行材料后，能否独立完成不同输入的新任务 | 撤销不能可靠收回旧明文；任务绑定也不能消除有效账号代理或慢速提取 |

以真实行为驱动验收：分析者不必理解所有混淆，可能转向观察或执行。不要按某个工具名字封堵，也不把 Skill 模块目录数当作独立算法、可用工具或成功案例数量。拆分“流程建议、模板、可执行实现、已验证结果”；同一模板出现在多个模块中，不增加证明力度。以上是从公开工作流归纳的防御推论，不是针对某个工具的防护实测。

## 验收与研究可信度

- 定义成功目标：读出字符串、恢复函数、重建程序、获得新的受限业务结果分别记录；约定工具、模型、提示、时间预算与人工介入。
- 把原始输入、预期结果和构建答案与被分析环境隔离。最终用干净环境和未泄露的输入重跑交付物，确认它依赖待测产物，而非硬编码答案、历史会话或测试后端管理权限。
- 优先验证样例有合法成功路径。检查位宽、符号、溢出和约束是否冲突；无解样例不能证明防护有效。分支强制执行不证明真实可达，有限轨迹不证明完整 CFG。
- 对恢复结果检查边界输入、不同分支、数组及别名、外部调用、错误路径和状态变化。随机回归通过不等于全输入证明；语义化简也不保证可重编译和 ABI 正确。
- 小样本、旧模型直接读汇编失败，只能支持该配置下的结果；不能外推到更新模型、带工具的 Agent 或所有虚拟机保护。可读性提高也不等于语义正确。

上述方法对应受限实验与工具能力，不能据此宣布任何当前商业产品已被攻破。论文给出模型与任务边界，Quarkslab 给出探索性实验中的环境污染、结果验证与动态分析教训：[2025 四维框架论文](https://arxiv.org/html/2505.19887v2)、[2026 BinDeObfBench](https://arxiv.org/html/2604.08083v1)、[Quarkslab 原文](https://blog.quarkslab.com/defeating-ai-assisted-reverse-engineering-or-at-least-trying-to.html)。两篇看雪材料的取舍见仓库 docs/research/ai-re-review-2026-10-24.md；独立安装包以本页指导为准。
