# 重点保护检查

按实际证据选择检查项，不把整张清单机械输出给用户。

## 资产与执行链

| 检查对象 | 需要回答的问题 | 优先措施 |
| --- | --- | --- |
| 签发私钥、管理 token、云服务凭据 | 是否存在于源码、历史、包资源、日志、配置或客户端内存中？ | 移出客户端；如确认泄漏则安排轮换与失效，清除当前构建不足以修复泄漏 |
| 核心算法、规则、模型、付费资源 | 是否必须完整下发？被复制后的商业影响？ | 可接受时将关键能力保留服务端；必须离线则说明可提取性，并评估编译、混淆及分层分发 |
| 授权决策与付费能力入口 | CLI、GUI、插件、脚本、后台任务是否走同一授权链？ | 在实际执行边界校验；共享校验层避免规则漂移，关键操作保留独立授权检查 |
| 服务端 API | 跳过客户端后能否直接调用？是否只依赖可伪造设备 ID？ | 服务端身份与授权检查、对象归属检查、速率及资源配额 |
| 本地许可证与缓存 | 是否验证签名、产品、有效期、设备与功能？是否信任可写布尔值？ | 验签后验证全部业务声明；状态缓存不是权威授权来源 |
| 设备与席位 | 克隆、重装、硬件更换、虚拟机和并发激活如何处理？ | 说明绑定强度、隐私与恢复策略；服务端并发一致性 |
| 更新和插件链 | 更新来源、签名及防降级是否可信？插件能否绕过关键入口？ | 受信发布链、更新验证、必要的版本兼容和最低版本策略 |
| 发布产物 | 源映射、调试日志、测试授权和管理工具是否随包发布？ | 产物扫描；调试符号可私有保留以便诊断；验证最终包而非仅源码 |

根据项目区分：Python 包装为 EXE 不等于源码机密；Electron/浏览器资源按可读材料考虑；.NET/Java 元数据增加可分析性；原生程序也能被分析和修改。只写实际相关的判断，不强制用户重写语言。

## 产品价值与复制路径

对算法、模型、资源与可重做的能力，先按 [value-and-copy-paths.md](value-and-copy-paths.md) 建立最短复制路径与项目适配方案。资源复制或功能替代可能完全不触及授权，按实际商业影响排序。

## 风险排序

结合影响、暴露程度、利用条件、现有控制及修复成本排序。优先处理能批量伪造授权、访问服务端资源或泄露高权限凭据的问题，再处理本地绕过和资源复制，再考虑增加逆向成本的措施。允许依项目调整顺序。

建议发现表字段：优先级、资产/位置、可核对证据、可能结果、修复动作、成本、验收方式。推测项写“待确认”，不要伪造精确风险评分。

不要将调试器检测、进程扫描、反虚拟机或层层加壳作为通用默认方案。评估兼容性、误报、签名、杀毒、性能、可维护性和用户恢复成本。
